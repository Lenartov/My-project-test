# Пайплайн островів: Blender → Unity

Цей документ — точка входу для автора островів, Blender/MCP-агента та Unity-агента. Мета: користувач описує бажаний острів, агент знаходить або створює потрібні моделі, збирає композицію, передає її в Unity, а Unity перевикористовує вже нарізану геометрію й запікає лише нову або змінену.

**Статус: спільний кеш Mesh/FragmentMeshData реалізовано в baker; JSON importer, Blender exporter та logical asset registry ще треба реалізувати.** Наявність прикладів JSON не означає, що імпортер уже працює. Ручна перевірка нового кешу в Unity ще потрібна.

## Що вже є, а що треба реалізувати

| Можливість | Поточний стан |
| --- | --- |
| Редагований source prefab → збережений fragment prefab | Є: `FragmentIslandAuthoring` і `FragmentIslandBaker` |
| Нарізка одного Mesh для кількох його екземплярів у межах острова | Є, якщо це той самий Mesh asset |
| Повторне використання запечених асетів екземплярами одного готового prefab | Є |
| Зв’язок із source та регенерація збереженого острова | Є: `FragmentIslandBakeRecord` |
| Синхронний reveal усіх моделей острова, сусідні межі, Open/Close | Є: `FragmentRevealGroup`, `FragmentIslandMap` |
| Різні розміри, XZ footprint, довільні docking ports, Gap 0 | Є: `FragmentIslandMapGenerator` |
| Загальний автоматичний кеш нарізки між різними островами | Є для Mesh/FragmentMeshData: однаковий source Mesh asset + Cell Size; матеріали поки локальні для острова |
| Бібліотека зіставлення `asset_id` → Unity asset | Треба реалізувати |
| Blender exporter та Unity importer описаного JSON | Треба реалізувати |
| Автоматичне додавання нового prefab до вибраного каталогу генератора | Треба реалізувати; зараз додавати до Templates вручну |

Видовжений тестовий `Island_Long` вручну використовує старі запечені ресурси квадратного острова. Регенерація source обох островів через оновлений baker переведе їх на спільний кеш. Готові assets цим оновленням коду автоматично не мігруються.

## Кінцевий робочий процес

1. **Запит користувача.** Опис форми платформи, біому, декорацій, розмірів і потрібних контактів. Якщо точних розмірів немає, агент обирає їх і повідомляє прийняті значення.
2. **Пошук у бібліотеці.** Blender-агент читає каталог. Вибирає наявні дерева, каміння та інші моделі. Створює лише відсутні моделі або свідомо нові варіанти.
3. **Композиція в Blender.** Острів складається з окремих екземплярів бібліотечних моделей. Платформа також є окремим asset і може бути унікальною. Композиція залишається редагованою.
4. **Передача.** Нові/змінені бібліотечні моделі передаються як FBX із матеріалами/текстурами; каталог і композиція — як JSON. Повторення дерева описуються посиланнями й transforms, без повторного експорту його геометрії.
5. **Імпорт у Unity.** Майбутній importer зіставляє `asset_id`, оновлює source prefab за `instance_id`, переносить footprint і порти. Невідомі або неоднозначні посилання дають явну помилку.
6. **Запікання.** Спільний кеш повертає готові Mesh/FragmentMeshData; нова або змінена геометрія нарізається. Матеріали поки зберігаються окремо в кожному острові.
7. **Результат.** Зберігається пов’язаний fragment prefab із `FragmentRevealGroup` та `FragmentIslandPorts`, готовий до розміщення й додавання в Templates. Острів має один спільний reveal, а не незалежну нормалізацію ефекту для кожного дерева.
8. **Наступні правки.** Оновлення композиції змінює source та пов’язаний результат. Перестановка моделей не повинна повторно нарізати їхню геометрію.

## Основні домовленості

- `asset_id` позначає бібліотечну модель; `instance_id` — конкретне її розташування; `island_id` — редагований острів. Назва об’єкта для відображення не є його ідентичністю.
- Повторне використання означає посилання на спільні Mesh/дані/текстури, а не копію байтів із таким самим ім’ям.
- Острів не об’єднується в один унікальний combined Mesh. Ієрархія й незалежні декорації зберігаються; кожна нарізана модель уже містить combined geometry своїх фрагментів.
- Біом не вимагає дублювати однакову геометрію. Інший матеріал може використовувати той самий Mesh; зміна форми моделі потребує оновлення геометрії.
- Контур і порти задаються явно. Кратність розмірів та квадратна гріда не потрібні. За замовчуванням Gap = 0.
- Нарізка відбувається в Editor; runtime працює зі збереженими ресурсами. Спільна геометрія не усуває вартість рендерингу всіх її екземплярів.
- Повна автоматизація означає узгоджені exporter/importer і кеш. Чат не повинен вигадувати наявні кнопки, меню, команди або готовність інструментів.

## Як працювати до появи автоматизації

Уже зараз можна створювати моделі як спільні assets, вручну збирати source prefab із їхніх екземплярів, задавати footprint/порти й користуватися baker зі спільним кешем геометрії. Blender-агент може підготувати JSON за цим контрактом для майбутнього імпорту або ручного відтворення Unity-агентом у межах дозволених дій.
