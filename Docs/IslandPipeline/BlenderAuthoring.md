# Створення острова в Blender/MCP

Спочатку прочитай [README.md](README.md). Ця інструкція описує авторинг і цільовий експорт; автоматичний exporter ще треба реалізувати.

## Бібліотека та композиція

Перед створенням геометрії перевір наявний каталог `asset_id`. Якщо потрібна модель уже є, використовуй її. Не створюй новий `asset_id` лише через іншу позицію, поворот, масштаб або назву екземпляра.

Одна бібліотечна модель може містити кілька MeshRenderer-сумісних частин, наприклад стовбур і крону. Повторні екземпляри мають спільні mesh data й матеріали. У Blender для цього використовуй linked data/Linked Duplicate; у Python не викликай `mesh.copy()` для звичайного повторення. Не змінюй спільні mesh data, коли потрібно змінити лише один екземпляр: для справді нової форми створи окремий варіант із новим `asset_id`.

Платформа, дерева, каміння, кущі й статичні маркери залишаються окремими об’єктами. Не зливай цілий острів і не експортуй його як єдиний унікальний Mesh. Розміщуй композицію під одним коренем; допоміжні групи дозволені. Зберігай стабільні `island_id`, `instance_id` та `parent_id` після повторного відкриття `.blend`.

## Моделі

- Геометрія — статичні meshes; SkinnedMeshRenderer не входить у цей пайплайн. Окремі фізичні уламки, Rigidbody та colliders для ефекту не потрібні.
- Нормалі й UV мають відповідати бажаному зовнішньому вигляду. Перед експортом прибери ненавмисні дублікати граней і нульові полігони. Відкриті/тонкі поверхні не заборонені штучно, але результат їх нарізки потребує перевірки.
- Поточний fragment shader насамперед відтворює base texture, tint, vertex colors і alpha cutout. Не обіцяй відтворення довільних Blender procedural materials, складної прозорості чи всіх PBR-ефектів. Потрібні процедурні кольори/текстури підготуй для цільового матеріалу.
- Повторно використовуй матеріали й файли текстур. Зміна кольорової схеми сама по собі не потребує нової геометрії дерева.
- Для канонічної моделі зафіксуй масштаб, pivot та орієнтацію до широкого перевикористання. Для дерева/каменя зручний pivot на рівні опори; для платформи — на рівні верхньої поверхні поблизу центру.
- Зміна pivot у вже використаного asset може зсунути всі його екземпляри: це міграція моделі, а не непомітне виправлення експорту.
- Масштаб екземплярів, включно з нерівномірним, дозволений. Не застосовуй scale до окремої копії з дублюванням Mesh лише заради розтягнення. Уламки спільної нарізки також масштабуються; однаковий фізичний розмір уламків за різного scale не гарантується.
- Модифікатори канонічного asset мають бути відтворені в експортованому Mesh. Якщо модифікатор робить геометрію екземпляра іншою, це вже окремий варіант геометрії. Не апроксимуй shear як TRS мовчки.

## Footprint та порти

Контур описує зайняту платформою/обов’язковими перешкодами площу зверху, у XZ Unity. Це один простий замкнений полігон без дірок і самоперетинів; увігнуті форми дозволені. Не дублюй останньою точкою першу. Не включай розліт фрагментів у footprint. Декорації поза ним можуть перетинати сусідній тайл — вирішуй це свідомо й повідомляй про такі виступи.

Порт містить стабільний `port_id`, точку контакту, нормаль назовні та reveal boundary або його ширину. Для кількох сусідів на одній довгій стороні потрібні кілька портів. Одна точка стикування використовується одним зв’язком; розмір сусіда не зобов’язаний бути кратним довжині сторони. Геометрія й можливі виступи мають відповідати такому розташуванню.

За Gap 0 збігаються точки контактів, а нормалі спрямовані протилежно. Генератор не переробляє Mesh і не робить автоматично суцільний шов між несумісними кривими краями. Для суцільного проходу змоделюй сумісні ділянки біля портів. Height не впливає на reveal-відстань, але висота точки контакту використовується під час стикування.

## Експорт і передача

1. Збережи редагований `.blend` із композицією, бібліотечними зв’язками й ID.
2. Експортуй нові/змінені бібліотечні assets у FBX за стабільними шляхами. Матеріали та залежні текстури мають бути доступними. Не експортуй незмінені моделі окремо для кожного острова.
3. Онови каталог і опиши всі екземпляри, групи, footprint та порти у JSON за [TransferFormat.md](TransferFormat.md). Не додавай Unity GUID чи `.meta` з боку Blender.
4. Координати JSON уже мають бути в узгодженій системі Unity. Перевір відповідність експортованих FBX і JSON: осі, одиниці, pivot, rotation та scale.
5. Перевір, що всі `asset_id` вирішуються через каталог або відому Unity-бібліотеку. Нові/оновлені моделі мають фактичні файли, а не лише назви чи обіцянку експорту.
6. Передай список створених/перевикористаних assets, шлях до island JSON, розміри платформи та кількість портів. Вкажи невиконані кроки й відомі візуальні обмеження.

Повний FBX острова можна додати як необов’язковий візуальний reference. Він не є основним джерелом бібліотечної геометрії. Для старих повних FBX можливий окремий процес заміни частин бібліотечними prefab за `asset_id` зі збереженням transforms; автоматичне зіставлення за схожістю чи лише за назвою не передбачається.

Довідка про спільні mesh data: [Blender Linked Duplicate](https://docs.blender.org/manual/en/5.0/scene_layout/object/editing/duplicate_linked.html). Спосіб виконання команд через MCP залежить від фактично доступного Blender connector; ця документація не задає вигаданих MCP-команд.
