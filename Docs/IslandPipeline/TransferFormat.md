# Контракт передачі, version 1

**Цільовий контракт; exporter та importer ще не реалізовані.** Це не поточний формат Unity-серіалізації. Приклади: [каталог](Examples/library.assets.json) і [острів](Examples/Island_Forest_A.island.json). Значення `format` та `version` мають перевірятися імпортером; непідтримувана версія дає явну помилку.

## Пакет

Пакет містить `library.assets.json`, один або кілька `*.island.json` та потрібні нові/змінені FBX і текстури. Шляхи каталогу відносні до папки каталогу, `asset_library` — до island JSON. Використовуй `/`; абсолютні шляхи, вихід через `..` за межі пакета та неявне завантаження з мережі не входять у контракт.

Файли незміненої моделі можуть не передаватися повторно, якщо Unity-бібліотека вже однозначно знає її `asset_id`. Відсутній невідомий asset або заявлене оновлення без файлів — помилка. Передача оновлення моделі визначається наявністю її payload за `model_path`; імпортер звіряє фактичний вміст, а не лише ім’я чи дату.

## Каталог assets

Корінь: `format: "island_asset_library"`, `version: 1`, `assets: [...]`.

| Поле asset | Значення |
| --- | --- |
| `asset_id` | Стабільний унікальний ID, наприклад `Tree_Pine_A`; регістр має значення |
| `model_path` | Відносний шлях до канонічного FBX; для повторного використання відповідає відомому asset |

Каталог може містити більше моделей, ніж використовує один острів. Один ID відповідає одній редагованій бібліотечній моделі, яка може мати кілька дочірніх meshes. Оновлення вмісту не змінює ID, якщо це заміна тієї самої моделі; новий художній варіант отримує новий ID. Однаковий FBX не слід реєструвати під кількома ID без причини. Unity GUID, local file IDs, importer settings та cache hashes веде Unity-сторона.

Усі зовнішні текстури мають входити в передачу або вже існувати як однозначно відомі залежності. Матеріали екземплярів у version 1 задаються канонічною моделлю; окремий JSON-контракт material overrides поки не вводиться. Відмінні матеріальні варіанти можуть бути окремими бібліотечними конфігураціями зі спільними Mesh, без копіювання геометрії.

## Координати

`coordinate_space` має значення `unity_y_up_z_forward_meters`. Одна одиниця — один метр. Масиви `position`, `scale` та normal мають порядок `[x,y,z]`, quaternion — `[x,y,z,w]`. Усі числа скінченні, scale ненульовий, quaternion нормалізований. JSON не містить Blender Euler angles чи градусів.

Експортер виконує перетворення один раз. Unity importer читає ці координати без повторної зміни осей. Для цього контракту authoring frame у Blender — X вправо, Y уперед, Z вгору; явне відображення в Unity:

```text
C * [x, y, z] = [x, z, y]
position_unity = C * position_blender_in_meters
rotation_matrix_unity = C * rotation_matrix_blender * inverse(C)
scale_unity = [scale_blender.x, scale_blender.z, scale_blender.y]
```

Quaternion потрібно отримати з перетвореної rotation matrix, а не переставити його компоненти навмання. Наприклад, Blender `[1,2,3]` метрів стає Unity `[1,3,2]`; identity rotation залишається identity. Враховуй Blender scene units під час переведення в метри.

FBX після імпорту повинен мати ту саму орієнтацію, одиниці й pivot, що й asset у JSON. Самої перестановки позицій недостатньо: геометрія, winding/normals і transforms повинні узгоджуватися. FBX exporter/importer може вже перетворювати осі; не застосовуй перетворення вдруге. Перед серійною роботою перевір один асиметричний asset із позначеними front/up/right, rotation 90°, різними scale по осях і дочірнім об’єктом. Не підбирай осі окремо для кожного острова.

## Опис острова

Кореневі поля: `format: "fragment_island"`, `version: 1`, `coordinate_space`, `island_id`, `asset_library`, `bake`, `nodes`, `footprint`, `ports`.

- `island_id` — стабільна ідентичність острова; повторний імпорт оновлює пов’язаний source.
- Корінь острова має position zero, rotation identity та scale one. Масштабування описується transforms дочірніх nodes; це правило обміну, а не заборона наявних Unity prefab із root scale.
- `bake.cell_size` — скінченне додатне число в локальних одиницях канонічного Mesh, як у поточному baker. Це не розмір гріди карти. Інші reveal settings при повторному імпорті зберігаються з Unity source; під час першого імпорту використовуються чинні defaults.
- `nodes` — повний актуальний список керованих importer-ом об’єктів, а не список дельт.
- `footprint` — впорядковані `[x,z]` у просторі кореня острова, мінімум три точки. Полігон не містить дірок, самоперетинів і дубльованої останньої точки. Обидва напрямки обходу дозволені.
- `ports` — повний актуальний список контактів острова. Назви не зобов’язані бути cardinal. Для ізольованого авторингу список може бути порожнім; для процедурного генератора потрібен щонайменше один валідний порт.

### Node

| Поле | Правило |
| --- | --- |
| `instance_id` | Унікальний стабільний ID у межах острова; не індекс у списку |
| `parent_id` | ID іншого node або `null` для кореня; цикли заборонені |
| `asset_id` | ID із бібліотеки або `null` для порожньої групи |
| `name` | Людинозрозуміла назва; може змінюватися без зміни ID |
| `position` | Локальна позиція відносно parent |
| `rotation` | Локальний quaternion відносно parent |
| `scale` | Локальний scale відносно parent |

Батьківський node не обов’язково передує дочірньому у файлі; importer має розв’язати ієрархію за ID. `asset_id: null` не означає пропущену модель. Невідомий непорожній ID не замінюється мовчки порожнім GameObject. Внутрішня структура бібліотечного asset переноситься його Unity prefab; `nodes` описує розміщення цих assets і допоміжних груп.

### Port

| Поле | Правило |
| --- | --- |
| `port_id` | Стабільний унікальний ID у межах острова |
| `position` | `[x,y,z]` точки контакту в island-local просторі |
| `outward_normal` | `[x,0,z]`, одиничний напрямок назовні |
| `width` | Додатна довжина автоматичної reveal-лінії за відсутності boundary |
| `boundary` | Масив island-local `[x,y,z]`: порожній або щонайменше дві різні XZ точки |

Непорожня boundary — відкрита ламана для reveal-впливу. Вона має пріоритет над width; position лишається точкою стикування й не зобов’язана бути її серединою. Порожня boundary утворює пряму лінію, центровану на position і перпендикулярну normal. Автоматичне визначення контакту за всією геометрією не є частиною контракту.

Відповідність поточним Unity полям: `port_id` → `FragmentIslandPort.id`, `position` → `attachmentPosition`, `outward_normal` → `attachmentNormal`, `width` → `attachmentWidth`; `useCustomAttachment = true`. Boundary імпортується enabled/open. Footprint і порти записуються на source authoring, щоб baker переніс їх у результат.

## Оновлення та помилки

Незмінений `instance_id` зберігає Unity-ідентичність об’єкта навіть після rename/reparent. Відсутній у новому повному списку node видаляється лише з керованої композиції цього острова; його бібліотечний asset лишається. Інші сцени та острови не перебудовуються мовчки.

Дублікати ID, цикли, невідомі assets, некоректні transforms, відсутні потрібні файли, непідтримувана версія чи некоректний footprint мають завершити перевірку помилкою до заміни останнього працездатного prefab. Не виправляй невалідний пакет видаленням проблемних об’єктів без повідомлення.
